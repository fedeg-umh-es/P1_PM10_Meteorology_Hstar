# Blocking issues — IJER Madrid–Ireland forensic gate

This list separates what actually blocks submission from what is disclosed, justified, or merely informational. See `forensic_gate_report.md` for full detail and evidence per item.

## Blocking

1. **Madrid meteorological-covariate count mismatch (text vs. code).** `manuscripts/manuscript_main.tex` states the "lags + meteorology" condition adds "nine concurrent meteorological covariates measured at forecast origin t." This is true for the 8 Irish stations (`code/e2_met_ireland_config.json`: 9 features) but **false for Madrid** (`code/e2_met_madrid_config.json`: 7 features — `temp_c, humidity_pct, pressure_hpa, wind_speed_ms, wind_dir_deg, solar_rad_wm2, precip_mm`). Madrid is the site carrying the paper's headline result (ΔH\*=+8). A reviewer who checks the code against the text will find a direct contradiction about the paper's own central methodology. **Requires either a text correction (state the two different feature sets/counts explicitly) or a code fix, before submission.**

2. **No original primary evidence exists for the Ireland experiment.** Confirmed via `results/e2_met_ireland_pm10/run_metadata.json` (itself a forensic note, not real metadata): no `run_metadata.json` for the original Ireland run exists anywhere in this repository's git history, and `code/e2_met_ireland_config.json` hardcodes a dataset/results path on the original author's machine that was never reachable from this repo. Everything the manuscript cites for Ireland traces only to `results/e2_met_ireland_pm10_regenerated/`, explicitly self-labelled `"REGENERATED FROM RECOVERED SOURCE DATA — NOT the recovered original execution."` This audit confirmed the regenerated bundle is internally hash-consistent and numerically matches the manuscript, but it is a reconstruction, not the original primary evidence. **This is disclosed nowhere in the manuscript itself** (only in internal `docs/audit/` notes) — the paper should either state that Ireland results were regenerated from recovered source data, or this should be resolved before submission.

3. **Madrid's raw aligned dataset is absent from this clone**, and the tracked `run_metadata.json` for Madrid describes only a partial (first, `lags_only`-only) sub-run that contradicts the final tracked bundle's actual contents. The contradiction is honestly disclosed in `results/e2_met_madrid_pm10/bundle_provenance.md`, but the underlying `run_metadata.json` file itself remains uncorrected, and no hash manifest exists for Madrid outputs (this audit computed one; see `madrid_primary_evidence.csv`). Combined with item 2, **neither of the paper's two experimental sites has a fully reproducible, hash-verified, end-to-end primary-evidence chain** — only a verified chain from tracked intermediate outputs onward.

## Not blocking (verified, justified, or already correctly handled)

- **Madrid headline numbers** (362 origins, H\*=9/17, ΔH\*=+8, bootstrap median +3, CI [-8,+12], P=0.7445) — independently recomputed by this audit from raw predictions and the raw 2000-resample bootstrap table, exact match. Not a blocker.
- **XGBoost expanding-window vs. SARIMA rolling-2-year-window asymmetry** — real, but disclosed in the Methods section and justified by SARIMA/Kalman-filter tractability limits. The paper's own "expanding-window" description (line 157) accurately matches the code. Not a blocker, though Table 1's "Training: 2020–2022" caption is worth a clarifying footnote (it describes the descriptive-statistics window, not the model's per-origin training window, and doesn't disclose Madrid's `train_start=2019-01-01`).
- **Portlaoise h=24 "undetermined" DM-HLN statistic** — root-caused to a numerical non-positive-definiteness of the unweighted-kernel HAC long-run variance estimator at `max_lag=23, n=212`. Predictions differ substantially between conditions at this station×horizon (`max_abs_pred_diff=13.37`); this is not a feature-delivery or support-alignment defect, and the canonical table already correctly marks it `undetermined` rather than fabricating a p-value. Not a blocker.
- **Uneven cross-station support** (Dublin Airport n=145, Dundalk n=154 vs. ~211–212 for other stations) — traced to genuine raw-data availability gaps (source files ending early), consistent with the manuscript's own disclosed range ("145 to 212 origins"). Not a blocker.
- **Figures** — the 4 figures actually included in the compiled manuscript are current and trace cleanly to the canonical CSVs (same regeneration batch). 6 additional unreferenced, stale figures exist under `manuscripts/figures/` but are not used anywhere in the compiled document. Not a blocker, but should be deleted or clearly marked archival to avoid future accidental reuse.
- **Henry Street ΔH\*=+7** and the 5 Irish ceiling-censored stations shown in the figures match the current canonical tables exactly; no stale value is being displayed.

## Final verdict

**`BLOCKED_BY_MULTIPLE_CRITICAL_ISSUES`**

Rationale: no single issue invalidates the manuscript's core numeric findings — every headline Madrid number was independently reproduced by this audit from genuine primary evidence, and the Ireland regenerated evidence is internally consistent. But three distinct, non-overlapping defects remain unrepaired and each would independently draw reviewer objection: (1) a factual contradiction between the manuscript's stated Madrid meteorological predictor set and the actual code, (2) the complete absence of original (non-regenerated) primary evidence for the Ireland experiment with no disclosure of this in the manuscript, and (3) an uncorrected, contradictory `run_metadata.json` for Madrid with no accompanying hash manifest. None of these requires re-running any experiment (no COVID sensitivity, no Ridge, no figure regeneration needed to fix them) — they require targeted text/documentation repair and, for item 1, a decision on which feature set is authoritative for Madrid.
